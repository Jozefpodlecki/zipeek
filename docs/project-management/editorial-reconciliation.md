# Editorial reconciliation inventory

The maintained documentation must state current product requirements separately from observations of the implementation. Earlier source assessments and release-era narratives are not accepted requirements and do not establish a successful current build or browser run.

The editorial audit found **53 maintained files** containing numbered development references. This is a source-text inventory, not proof of 53 incorrect product requirements. Original contents were preserved verbatim in the historical audit collection, with relative links adjusted for their archive location.

Of those files, **12** are historical reviews that now point to their appropriate current specification; **41** retain technical information without using numbered development snapshots as current authority. The preserved snapshots are for provenance and technical comparison, not instructions to restore old behavior.

## Review limitations

- Marker removal and provenance separation are not equivalent to a source-level technical audit. Assertions about package ownership, stored data, dependencies, route behavior, current content totals and browser availability must still be checked against current source and live tests.
- The records in the historical audit collection are frozen source evidence. Historical tests and release claims do not count as current passing verification.
- The maintained source-archive naming specification necessarily includes an abstract filename pattern. It does not cite a past numbered release as product behavior.
- Documentation validation checks link targets and the generated search index, but not Rust compilation, browser rendering, pedagogical correctness or licensing.
