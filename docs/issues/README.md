# Issue library

The issue pages are the authoritative location for user-reported UI, gameplay and service defects. Reports reflect user observation, not verified failing tests.

## Workflow

Status progression: Open -> In Progress -> Implemented -> Verified -> Resolved. An implemented code change does not close an issue until the reported behavior is verified. Keep stable IDs and do not reuse them.

Issues are grouped by feature. Screenshot assets are under `assets/screenshots/`. Images are evidence of what was visible at capture time, not proof of the exact cause. Some reports share one screenshot. Images cannot establish hidden state or console errors on their own.
