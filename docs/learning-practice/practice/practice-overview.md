# Practice overview

Practice has separate setup, active-session and completion stages. The shared session controller manages configuration, persistence and outcomes; exercise components provide their particular interactions.

## Authoritative behavior

- [Session setup](practice-session-builder.md) describes exercise and vocabulary configuration.
- [Shared exercise foundation](shared-exercise-foundation.md) describes reusable Yew layout and behavior.
- [Outcomes and Word mosaics feedback](practice-outcomes.md) defines the three verdicts, attempts, Skip and Replace, and shared exercise presentation.
- [Portable profiles](practice-profile-portability.md) defines local profile JSON import/export.
- [Learning evidence](../practice/learning-evidence.md) distinguishes learning evidence from simple completion.
- [Vocabulary eligibility](../../dictionary-data/vocabulary/vocabulary-selection.md) controls exclusions and visitation policy.

For current visual design see [Practice UX](../../product-ux/practice/ux-practice-setup.md) and [global UX](../../product-ux/ux.md). Historical Practice notes have been retained for provenance in [the archive](../../archive-history/audits/PRODUCT_PRACTICE.md), not as active behavior.

## AI narrative exercises

Story Builder and Reading Comprehension use separate 5–10 sentence passage settings. Conversation Practice uses a separate 5–10 turn setting. See [AI narrative exercises](ai-narrative-exercises.md) for the validation contract and implementation limitations.
